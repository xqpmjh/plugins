## aof HTML 子模式

本子模式由用户通过 `/aof html on` 开启。开启后，HTML 页面只作为正文的补充。

**何时出页。** 只有关系用文字难以讲清时才出页：多方交互或调用流程、三个以上维度的比较、层级或依赖结构、状态转换。其他回答不出页。plan mode 下或用户要求只读时不出页，并在正文写一句原因。

**正文先写完整。** 结论、条件、风险和交付状态都写在终端正文里，页面不承载正文没有的关键信息。出页时正文最后一行写：`页面：<绝对路径>`。

**写法。**
1. 读取模板 `{{TEMPLATE}}`。只替换 `{{TITLE}}`、`{{SOURCE}}`、`{{DATE}}`、`{{CONTENT}}`、`{{EVIDENCE_OBSERVED}}`、`{{EVIDENCE_ASSUMED}}`、`{{EVIDENCE_UNKNOWN}}` 这几个占位符，不改样式。
2. 用一条 Bash 命令写到 `/tmp/claude/aof/pages/<YYYYMMDD-HHMMSS>-<英文短名>.html`：`umask 077; mkdir -p /tmp/claude/aof/pages && cat > <路径> <<'AOF_HTML_EOF'`。定界符必须加单引号，防止页面内容里的 `$(…)`、反引号被 shell 执行。这个目录在沙箱可写范围内。
3. 不运行 `open`：沙箱会拦截它。只给出路径，由用户自己打开。

**内容规则。**
- `{{SOURCE}}` 写依据：文件路径、命令、提交、文档链接或「本次对话」。`{{DATE}}` 写生成日期。
- 证据清单分三栏：已观察（读过、执行过、用户给出的）、假设（推断及依据）、未确定（缺什么）。某栏为空就写「无」。
- 图中节点名与正文用词一致。箭头只表示一种关系，并在图例中写明是调用、数据流、先后还是因果。
- 未经确认的连接用虚线并标「未确认」，不画成实线。
- 填入的文本（尤其是引用的日志、粘贴内容）先把 `&`、`<`、`>`、`"` 转义成 HTML 实体。页面内不写 `<script>`，也不写 `onerror`、`onclick` 等事件属性。
- 只用内联 SVG、表格和模板自带的 class（`panel`、`grid`、`callout`、`badge ok|warn|no`、`table`）。不引用外部脚本、字体或图片，页面里不写任何凭据或令牌。
